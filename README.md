# 院内タスクボード

歯科医院内で使う、チェアサイド入力に特化したシンプルなタスク管理Webアプリです。日々の診療、医院運営、発注、患者関連準備、事務作業で「後でやること」を忘れないためのローカルMVPです。

## 使い方

`index.html` をブラウザで開くと利用できます。スマホやiPadでは、ブラウザの「ホーム画面に追加」からアプリ風に起動できます。

右下の大きな `＋` ボタンからタスクを登録します。

1. タスク種別を選ぶ
2. 必要な場合だけカルテ番号を入力する
3. 期限を選ぶ
4. 必要なら短いメモを書く
5. 保存する

タスク種別を選ぶと、タスク名にはその名称が自動入力されます。カルテ番号を入力した場合、表示は `#12345 インプラント体発注` のようになります。

## 画面

- 今日やる: 今日が期限、または期限切れの未完了タスク
- 期限が近い: 期限切れ、今日、明日、7日以内のタスク
- 患者関連: カルテ番号があるタスク
- 発注・準備: 発注・準備タグが付いたタスク種別のタスク
- 後で整理: 期限なし、その他、種別未選択のタスク
- 完了済み: 完了したタスク
- タスク種別: 種別マスターの追加・編集・並び替え・非表示・削除
- 設定: JSONエクスポート・インポート

## タスク種別の編集

タスク種別は `taskTypes` として保存します。コード固定の配列だけにせず、localStorage上で編集できます。

各タスク種別は以下を持ちます。

- `id`
- `name`
- `sort_order`
- `active`
- `chart_number_mode`
- `default_due_type`
- `created_at`
- `updated_at`
- `category_tags`

`chart_number_mode` は `required`、`optional`、`none` の3種類です。発注・準備ビューへの表示は `category_tags` の `order_prepare` で管理します。

過去タスクで使われた種別は、履歴を壊さないため完全削除ではなく原則 `active=false` の非表示にします。未使用の種別だけ完全削除できます。

## カルテ番号と患者情報の扱い

このアプリでは患者名を保存しません。生年月日、住所、電話番号、病名、詳細な医療情報も保存しない方針です。

保存する患者関連情報は、タスクに紐づくカルテ番号だけです。カルテ番号は院内では患者を特定できる情報として慎重に扱ってください。患者マスターは作りません。

## JSONバックアップ

localStorage版のため、バックアップ用にJSONエクスポート・インポートを用意しています。

エクスポート時には次の注意を確認してください。

> このデータにはカルテ番号が含まれます。外部共有や送信に注意してください。

インポート時は既存データを上書きします。誤上書きを防ぐため、読み込み前に確認ダイアログを出します。復元前には現在のJSONを書き出してください。

## 保存方式

保存先はブラウザのlocalStorageです。保存キーは以下です。

```text
clinicTaskBoard.v1
```

同じ端末・同じブラウザ内でのみ保存されます。スマホと院内iPadの同期はまだ行いません。

## PWA

`manifest.json` と `service-worker.js` を用意しています。ローカルHTTPサーバー、またはHTTPS環境で開くとService Workerが登録され、最低限のオフライン表示に対応します。

## 将来Supabase化する場合

今回のMVPではSupabase接続は実装していません。将来同期する場合は、以下を検討してください。

- `tasks` テーブルと `task_types` テーブルに分ける
- `id`、`created_at`、`updated_at` はUUID/タイムスタンプとして扱う
- Supabase Authを使う
- RLSを必ず有効にする
- 院内iPad用アカウントと個人スマホ用アカウントを分ける可能性を考える
- カルテ番号の閲覧範囲を最小化する
- 患者名や患者属性情報を追加しない方針を維持する

Supabase化するときの主な変更箇所は `assets/js/app.js` の `loadState()`、`persist()`、タスク保存系関数、タスク種別保存系関数です。現在はlocalStorageを単一ストアとして扱っているため、この層をAPI呼び出しに差し替える設計にしています。

## 固定方針

- 患者名は保存しない
- カルテ番号のみをタスクに紐づける
- タスク種別は後から編集できる
- 既存履歴を壊さないため、使用済み種別は非表示で残す
- JSONを書き出すときはカルテ番号を含むことを必ず警告する
